# 小马学习报告 2026-05-11

## 概述

今日学习围绕 Hermes Agent 展开，上午从宏观视角梳理了 v0.12/v0.13 的核心新特性，下午进行了深度专题研究。收获最大的是理解了两个重大版本迭代之间的内在联系：v0.12 的 Curator 技能管家和 v0.13 的 Kanban 多 Agent 协作并非孤立功能，而是一个完整自维护系统的两个层面。以下按主题整理要点。

---

## 内容详解

### 一、v0.13 The Tenacity Release — 让 Agent 有始有终

**2026-05-07 发布的 v0.13** 是目前最新稳定版，主题是解决"Agent 任务容易卡死/跑偏"的长久痛点。

**Multi-agent Kanban 系统**是最大亮点：用户创建一个看板，向其中投入任务，多个 Hermes Worker Agent 自行认领、执行、交接、关闭。系统内置四大保障机制：

- **心跳机制（heartbeat）**：定期检测任务是否还活着，防止静默挂起
- **僵尸检测（zombie detection）**：识别卡死任务并标记，供人工介入
- **自动重试（retry budgets）**：单任务级别的重试次数控制，避免无限循环
- **幻觉门（hallucination gate）**：防止 Agent 虚构执行结果就标记完成

**`/goal` 命令（Ralph Loop）**解决大模型常见跑题问题——将 Agent 锁定在一个目标上，跨轮对话保持焦点，不因上下文转换而遗忘主任务。

**Checkpoint v2** 重写状态持久化：真正的剪枝（而非只写不删）、磁盘保护 guardrails、消除孤儿 shadow repo，并增加了**写后 lint**——`write_file` 和 `patch` 操作后自动检查 Python/JSON/YAML/TOML 语法错误。

**`no_agent` cron 模式**允许 cron 任务完全不带 Agent，只运行脚本。stdout 空则静默，有输出则原文投递，适合定时备份、定时推送等纯脚本场景。

---

### 二、v0.12 The Curator Release — 自治技能管家

**2026-04-30 发布的 v0.12** 带来 Hermes Agent 的自治自我维护能力，这是项目核心理念"运行越久能力越强"的关键支撑。

**Curator 后台代理**运行机制：
- 默认在网关 cron ticker 上按 **7 天周期**自动调度
- 对 skill 库打分、合并、清理，写运行报告到 `logs/curator/run.json` 和 `REPORT.md`
- 三种处理结果：**consolidated（合并）**、**pruned（修剪）**、**graded（评分）**，由 model + heuristic 共同判定
- **bundled/hub 技能**受保护不被 mutation
- 可通过 `hermes curator status` 查看技能使用排名

**自我改进循环（Self-improvement Loop）**从 v0.12 起做了substantially upgrade：
- **class-first（分类打分卡）**：从自由式判断改为基于评分卡的分类打分，决策更稳定
- **active-update bias**：优先更新 Agent 刚刚加载的那个 skill
- 支持 `references/` 和 `templates/` 子文件的处理
- **运行时继承**：父进程的 provider/model/credentials 现在真正传递到子进程（之前有 bug）
- 只允许 memory + skills 工具集调用，防止能力蔓延

---

### 三、Curator 与 Kanban 的协同闭环

v0.12 的 Curator 是"技能库管理员"，v0.13 的 Kanban 是"任务协作板"，两者有天然的协同关系：

**Curator 管理的 skills 可被 Kanban 的多个 Worker Agent 调用**——当某个 Worker 发现缺少某个 skill，Curator 可在后台评估是否需要创建新 skill 或从库中复用。这形成了一个**感知-决策-执行-反馈**的完整闭环，让 Hermes Agent 真正成为有自我维护能力的系统。

---

### 四、Skills 技能系统与 Cron 调度

Hermes 的技能系统是"按需获取的知识"，用于教授 Hermes 新的工作流程。支持**渐进式披露（Progressive Disclosure）**，技能元数据存储在 SKILL.md 中。支持技能中心搜索、社区共享的 agentskills.io 开放标准，以及平台特定技能（iOS/Android/Termux 分支）。

Cron 调度器内置，支持**任意平台交付**（origin 表示默认交付端）。任务可通过 `--context_from` 注入历史上下文，实现多时段工作流串联：10:00 收集 → 16:00 整理 → 21:00 发布。所有工具调用都有结构化输出，适合做日报/周报类的自动化报告。

---

### 五、新增平台与默认内置技能

v0.12 新增第 18 个消息平台**腾讯元宝**、Microsoft Teams 插件接入，以及 **Spotify/Google Meet 原生集成**。v0.13 新增 **Google Chat 成为第 20 个消息平台**，7 语种本地化（中日德西法乌土）也已落地。

**ComfyUI v5（图像生成工作流）**和 **TouchDesigner-MCP（实时视觉编程）**从 v0.12 起升级为默认内建技能，无需手动安装即可在 Agent 环境中调用，配合 AI 图像生成和实时视觉效果创作。

---

## 实践心得

1. **Cron + context_from 是自动化工作流的灵魂**：利用 `--context_from` 在不同时段任务间传递上下文，实现了"收集→整理→发布"的全自动流水线，完全无需人工干预
2. **Curator + Kanban 组合是未来方向**：自维护系统配合多 Agent 协作，让 Agent 真正具备长期自主运作能力，值得在个人工作流中深度使用
3. **写后 lint 很有价值**：Checkpoint v2 的 `write_file`/`patch` 语法检查可以避免很多低级错误，特别是在 JSON/YAML 配置文件中
4. **no_agent cron 模式很实用**：纯脚本定时任务不需要 Agent 介入，节省 token 消耗，适合备份、推送等基础设施任务
